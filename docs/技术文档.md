## 2. 项目概览

### 2.1 定位

一个部署在 Vercel 的网页控制台，把**英汉词表**（XLSX）加工成三类可打印/可听的教辅产物：

| 板块 | 入口 | 产物 | 算力位置 |
| --- | --- | --- | --- |
| 词表排版 | `/` | 五列表格 PDF、模板版 PDF / XLSX | **100% 浏览器** |
| 单词朗读 | `/tts` | MP3、二维码分享链接 | 服务端合成 + 浏览器合并编码 |
| 练习生成 | `/gen` | 测试卷 DOCX / 练习包 ZIP | **服务端**（LLM + Workflow 队列） |
| 移动播放 | `/listen?token=` | — | 只读展示 |

### 2.2 技术栈

| 层 | 选型 | 说明 |
| --- | --- | --- |
| 构建 | Vite 8 | `vite.config.js` 挂 3 个插件：`react()`、`nitro()`、`workflow()` |
| 前端 | React 19 | 无路由库、无状态管理库，全部 `useState` + `pathname` 前缀判断 |
| 服务端 | Nitro 3 (beta) | `nitro({ serverDir: './nitro' })`，输出 `.output/`，含 Vercel preset |
| 长任务 | Vercel Workflow (`workflow` ^4.6.2) | `'use workflow'` / `'use step'` 持久化执行 |
| 对象存储 | Cloudflare R2（S3 兼容） | `@aws-sdk/client-s3` + presigner |
| PDF | `pdf-lib` + `@pdf-lib/fontkit` | 前后端各有一套独立实现 |
| DOCX | **手写 OOXML** | 无 `docx` 依赖，见 `server/docx.js` |
| XLSX 读 | `xlsx` (SheetJS) | 浏览器端解析 |
| XLSX 写 | `exceljs` | 仅模板 XLSX 导出，动态 `import()` |
| TTS | Azure Speech（主）/ `edge-tts-universal`（备） | 详见 [5.4](#54-tts-双通道) |
| MP3 编码 | `lamejs` | **仅浏览器端**用于分段音频合并 |
| 二维码 | `qrcode` | `QRCode.toDataURL` |

### 2.3 计算边界（理解本项目的关键）

本项目的算力划分是刻意设计的，也是很多设计取舍的根源：

```
┌──────────────────────── 浏览器 ────────────────────────┐
│ XLSX 解析（SheetJS）                                    │
│ 标准 PDF 生成（pdf-lib + 嵌入 STSong 子集）              │
│ 模板版 PDF / XLSX 导出                                  │
│ Edge-TTS 分段音频合并 + MP3 编码（WebAudio + lamejs）    │
│ TTS 音频本地库（IndexedDB）                             │
└────────────────────────────────────────────────────────┘
                          ↓ 仅提交词表 / 音频 base64 / 查询任务
┌──────────────────────── 服务端 ────────────────────────┐
│ LLM 题目生成（唯一需要密钥的计算）                        │
│ DOCX / 翻译题 PDF / ZIP 打包                            │
│ Vercel Workflow 队列（可跨请求存活数十分钟）              │
│ R2 持久化（任务状态、缓存、产物、分享音频）                │
└────────────────────────────────────────────────────────┘
```

**设计含义**：

- 词表排版板块无任何服务端依赖，可离线使用，也不产生函数调用成本。
- 练习生成必须上服务端，因为需要 LLM 密钥，且耗时远超单次 HTTP 请求。
- Edge-TTS 走「服务端逐词合成 → 浏览器合并编码」，把 CPU 密集的 MP3 重编码从函数里挪出去，规避 Vercel Function 时限。

### 2.4 演进背景

仓库根目录的 `gen_engine.py`（约 86 KB）是**早期 Python 原型**：用 `python-docx` + `reportlab` + `nltk.wordnet` 在本机生成练习。当前的 `server/genEngine.js`（3380 行）是这个原型向服务端的移植与重构——题型、版式常量、分组语义都能一一对应，但同义词/反义词从 WordNet 改成了 LLM 生成。该文件现已不被任何代码引用，仅作历史留存。

## 4. 前端架构

### 4.1 路由与板块切换

**没有使用任何路由库**（全仓库无 `react-router` 引用）。路由是 `pathname` 字符串前缀判断：

| 代码 | 作用 |
| --- | --- |
| `src/App.jsx:95` | `getToolFromPath(pathname)`：`/tts*`→`'tts'`、`/gen*`→`'gen'`、其余→`'pdf'` |
| `src/App.jsx:101` | `getToolPath(tool)`：反向映射 |
| `src/App.jsx:116` | `activeTool` 惰性初始化自 `window.location.pathname` |
| `src/App.jsx:210` | 监听 `popstate` 同步（浏览器前进/后退可用） |
| `src/App.jsx:221` | `setTool` 内部 `history.pushState` |
| `src/App.jsx:281` | `/listen` 前缀直接早退渲染 `MobileListenPage` |

`/listen` 是唯一**不出现在导航栏**、也不经过 `activeTool` 的板块，只能由二维码链接进入。

**跨板块数据流**：只有 `App` 的三个 props 向下传递——`rows`（已解析词表）、`fileName`、`activeSheetName`。`TtsWorkspace` 额外接收 `loadWorkbook` 回调，可以在 TTS 板块内换工作簿并反向更新宿主状态。没有 Context、Redux 或 Zustand。

### 4.2 主控制台 `src/App.jsx`

**状态**（全部 `useState`）：`workbook` / `fileName` / `config` / `status` / `isLoading` / `exportingFormat` / `previewMode` / `previewPage` / `activeTool` / `fileInputRef`。

**派生数据**（`useMemo`）：

- `rows` ← `extractPairsFromSheet(worksheet, config)`；无工作簿时回退 `SAMPLE_ROWS`
- `previewRowScale` / `previewRowUnit` / `previewGridRatio`（`App.jsx:132-134`）：把 30 行基准的行高换算成当前 `rowsPerPage` 下的 CSS 值，使 HTML 预览与 PDF 的恒定正文高 264 mm 一致
- `stats`（`App.jsx:136-157`）：文件/工作表/单元格/页数统计

**XLSX 加载链路**：`readFileAsArrayBuffer` → `loadWorkbook`（`App.jsx:161`）→ `XLSX.read(data, { type: 'array', cellDates: true, cellText: true, WTF: false })` → `setWorkbook` + 自动切到第一个工作表。拖拽与隐藏 `<input accept=".xlsx,.xls">` 走同一路径。

> ⚠ `App.jsx:34` 有一行 `window.XLSX = XLSX`，因为 `src/utils.js:78` 通过 `window.XLSX.utils.decode_range` 使用它。这是一处隐式的全局耦合，重构时需要注意。

**预览双模式**：`'page'` 用 CSS Grid（`gridTemplateRows: 7.4fr repeat(N, Xfr)`）复刻 PDF 网格，第 5 列渲染 `/fourline.png` 四线三格，不足一页补空行；`'table'` 输出原始单元格地址与解析值，便于排查起始行列配置错误。

**配置项**：工作表 `<select>`、英语/汉语的起始行与起始列（4 个 `InputField`，列字段显示 A/B/… 后缀）、每页行数（上限 44）、最多读取行数（上限 10000）、四线三格开关。

**三种导出**（三条独立的实现路径）：

| 处理函数 | 调用 | 产物 |
| --- | --- | --- |
| `handleExportStandardPdf` | `createPdfFromRows` → `downloadBlob` | `pdf.js` 标准 PDF |
| `handleExportTemplatePdf` | `createTemplatePdfFromRows` → `downloadTemplatePdfBlob` | 模板版 PDF |
| `handleExportTemplateXlsx` | `createTemplateXlsxBlob` → `downloadNamedBlob` | 模板版 XLSX |

`extractPairsFromSheet` 的关键点：

- 行号参数与列号参数各自 clamp（行 1..100000、列 1..500、`maxRows` 1..10000）。

### 4.4 标准 PDF `src/pdf.js`

**页面与版式常量**：`MM_TO_PT = 72/25.4`；A4 纵向（595.28 × 841.89 pt）。

`TEMPLATE`（`pdf.js:12`）关键值：

| 字段 | 值 | 说明 |
| --- | --- | --- |
| `tableWidth` | 190 mm | 水平居中 |
| `headerHeight` | 7.4 mm | 表头 |
| `rowHeight` | 8.8 mm | **基准**行高 |
| `bodyHeight` | 264 mm | `8.8 × 30`，**恒定** |
| `fourlineHeight` | 6 mm | 四线三格高度，行高被压缩时垂直居中 |
| `columns` | `[9, 40, 31, 48, 62]` mm | 合计 190 mm |
| `headers` | `['序号','英文','默写汉语','中文','默写英文']` | |

**分页模型**：`getTemplateMetrics(rowsPerPage)` 令 `rowHeight = 264 / rowsPerPage`，**表格总高恒定**（`headerHeight + bodyHeight` ≈ 271.4 mm），行高随每页行数反比变化。这解释了 44 行上限的由来。

**绘制流程** `createPdfFromRows`（`pdf.js:268`）：

1. `Promise.all([fetch('/STSong.ttf'), fetch('/fourline.png')])`
2. `pdfDoc.registerFontkit(fontkit)` → `embedFont(cjkBytes, { subset: true })`（STSong 原始 11.7 MB，子集化后大幅缩小）；英文/数字用 `StandardFonts.Helvetica`
3. 逐页 `addPage` → `drawTemplatePage`：6 条竖线、表头线、`rowsPerPage+1` 条横线、表头文字 9.2 pt
4. 行内容：`rowFontScale = min(1, rowHeight / 8.8)`——**行高被压缩时字号按比例缩小**；英文列最多 2 行 9.3 pt，中文列最多 3 行 8.8 pt
5. 四线三格仅在 `showPracticeGrid` 时绘制，且只画在**第 5 列**
6. 页码为纯数字，7.5 pt Helvetica，居中于 `pageNumberY = 7.2 mm`（**不是**「第 X 页 / 共 Y 页」）

**排版算法**：`tokenize` 对含中文的文本走**字符级切分**（空白折叠为单空格 token），纯英文按空格切；`wrapTextByWidth` 按 token 累加 `font.widthOfTextAtSize` 测宽换行；`fitLines` 从 `startSize` 每轮 `-0.3 pt` 降到 `minSize`，同时满足宽度与最大高度约束（**字号自适应缩小**，而非溢出）。

若英文文本含非 Latin-1 字符（`/[^\u0000-\u00ff]/`），英文列会切换为 CJK 字体，避免 Helvetica 渲染缺字。

### 4.5 模板导出三件套

这是「标准 PDF」之外的**人教版模板版**导出，可出 PDF 或 XLSX，两页容量语义共用一套分页。

`src/templateLayout.js` 是版式的唯一事实来源：

| 导出 | 说明 |
| --- | --- |
| `TEMPLATE_PAGE_CAPACITIES` | **硬编码 55 个每页容量** `[41,41,39,39,41,41,38,40,…]`，注释说明这是「整页容量」而非末页实际行数 |
| `TEMPLATE_DEFAULT_PAGE_CAPACITY = 40` | 越界索引的返回值 |
| `getTemplatePageCapacity(pageIndex)` | |
| `paginateTemplateRows(rows)` | 按每页容量递进切片，返回 `{ pageIndex, startIndex, endIndex, capacity, rows }` |
| `TEMPLATE_PDF` | pt 单位的版式常量（`tableX 38.6`、`dataHeight 738.9`、`columns [30,124,90,149,108]` 等） |
| `TEMPLATE_HEADERS` | `['', '英文','默写汉语','中文','默写英文']`（第一列为空） |

**模板 PDF**（`src/templatePdf.js`）：独立于 `pdf.js` 的第二套绘制代码，复制了 `tokenize/wrapTextByWidth/fitLines` 但参数不同（`minSize 6.8`、步长 `-0.25`）。差异点：`drawCellText` 支持左/中/右对齐；页脚是完整的「第 X 页，共 Y 页」；正文只填 3 列（序号/英文/中文），**「默写汉语」「默写英文」两列留空**——这正是模板版的用途：留给学生手写。字体在**模块级 Promise 缓存**（`templatePdf.js:11`），比 `pdf.js` 更进一步。

**模板 XLSX**（`src/templateExport.js`）：以 `public/template-worksheet.xlsx` 为样式母版（`copyCell` 深拷贝 style），用 `exceljs` 动态 `import()` 写入。`buildPageSetup` 设置 A4、`scale 82`、`fitToWidth/Height: 1`、`printTitlesRow '1:1'`、`printArea A1:E{n+1}`。行高 `dataHeight / capacity / 0.82`（0.82 补偿打印缩放）。数据布局 `A=序号 / B=英文 / C=空 / D=中文 / E=空`。

四份导出实现**互不共享绘制逻辑**，只在数据层共享 `extractPairsFromSheet` 产出的统一 row 结构。

### 4.6 TTS 工作台 `src/TtsWorkspace.jsx`

**单词解析 `splitWords`**（`src/ttsUtils.js:13`）——最近的两次提交都在改这里，规则如下：

1. **词性 + 变形括号整体清洗**：`/\s+POS\.\s*\([^)]*\)/gi → ' '`。
   先于分词执行，避免 `oversleep v.(overslept ;overslept)` 中括号内的分号被误判为分隔符（提交 `2399796`）。
2. **紧跟单词的变形括号剥离**：`/[A-Za-z][A-Za-z'-]*\([^()]*\)/g`，匹配串含中文则原样保留，否则去掉尾部括号。
   `mean(meant,meant)` → `mean`；`shave(shaved,shaved/shaven)` → `shave`。
   因要求**无空格紧跟**，`go along (the street)`、`call (sb) back` 不匹配，释义括号得以保留（提交 `74898ee`）。
3. **分词**：`/[\n,，;；\t]+/`——换行、中英文逗号、中英文分号、制表符都是分隔符，**空格不是**（因此 `pay phone` 不被拆开）。
4. **逐项清洗**：去前导序号 `^\d+[.)、\s-]*`；去「词性 + 中文释义」尾注（`share vt. 分享` → `share`）。

> 已知行为（有测试断言）：`energy n. 精力；力量` 因分号先被切分，结果是 `['energy', '力量']`。见 `tests/ttsUtils.test.js`。

配套：`uniqueKeepOrder`（以 `toLocaleLowerCase` 为去重键，保序）、`chunkWords`（每批上限 80）。

**两条生成通道**：

| Edge | `POST /api/tts/edge`（`segmented: true`） | **逐词串行**合成，返回 `segments[{text, audioBase64, contentType}]` | `mergeSegmentBlobsToMp3` 合并 |

## 5. 服务端架构

### 5.1 Nitro 适配层与路由

`server/handlers/**` 全部写成 **Node/Vercel 风格 `(req, res)` handler**。`server/nitroAdapter.js` 负责与 Nitro 3 的 Web `Request`/`Response` 事件模型互转：

- `toNodeHeaders`：`Headers.forEach` → 小写键普通对象。
- `toBuffer`：null 保留；Buffer/Uint8Array 原样；其余 `Buffer.from(String(v))`。
- `runNodeHandler(handler, request)`（`nitroAdapter.js:18`）：
  - GET/HEAD 用空 body，其余 `await request.arrayBuffer()`，包成 `Readable` 造出 `req` 流，补 `req.method` / `req.url`（pathname + search）/ `req.headers`（含 `host` 兜底）。
  - **预解析 JSON**：`content-type` 含 `application/json` 且有 body 时直接设 `req.body`；解析失败则静默交给 handler 报 400。这正是 `auth.js:15`「`req.body` 已存在则直接返回」的配套设计。
  - 伪造 `res`：`statusCode` / `setHeader` / `getHeader` / `removeHeader` / `writeHead` / `write` / `end`；header 存 `Map`（小写键），body 收 `Buffer[]`。**未实现 `json` / `send` / `pipe` / `socket`**。
  - 汇总：数组值 `append`、null 跳过、body `Buffer.concat` → `new Response(body, { status, headers })`。

**限制**：全量缓冲（音频 base64 上传会临时占用约 2 倍内存）；无流式、无超时控制；依赖 `request.url` 为绝对 URL。

`nitro/routes/api/[...path].js` 是 catch-all 路由，用**精确匹配的 `Map<pathname, handler>`**（`replace(/\/$/,'')` 剥离尾斜杠）。因此路径必须逐字符匹配，无通配、无尾斜杠容错。query 不参与路由，所以 `?action=` 得以透传给 handler。未命中返回 404 `{ ok:false, error:'未找到对应接口。' }`。

> 仓库根目录的 `api/`（仅剩 `.DS_Store`）与 `routes/` 是历史残留，真实入口是 `nitro/routes/`。

### 5.2 认证与会话 `server/auth.js`

| 项 | 值 |
| --- | --- |
| Cookie 名 | `tts_session` |
| 有效期 | 12 小时（`SESSION_MAX_AGE`），**无滚动续期** |
| 属性 | `Max-Age=43200; Path=/; HttpOnly; SameSite=Lax` + `Secure`（当 `VERCEL_ENV` 存在时） |
| 签名 | `HMAC-SHA256(secret)` → `base64url`，secret 直接作 key，无 KDF |
| Cookie 格式 | `<expiresAt>.<nonce>.<signature>` |
| 校验 | `verifySession`：必须恰好 3 段 → 重算签名 → `Number.isFinite(expiresAt) && expiresAt > now && timingSafeEqual(...)` |

**无状态会话**：无服务端存储、无吊销列表。**登出只清 Cookie**，已签发的 Cookie 在 12 小时内仍然有效；改口令也不会使其失效，只有轮换 `TTS_SESSION_SECRET` 才行。

**口令校验**：`comparePassword` 直接与环境变量 `TTS_ACCESS_PASSWORD` 做 `timingSafeEqual`，**明文比对，无哈希**，单一共享口令。

**时序安全**：自定义 `timingSafeEqual(a, b)`（`auth.js:7`）在长度不等时直接 `return false`，否则调 `crypto.timingSafeEqual`。用于三处：Cookie 签名、口令、分享 token 签名。签名/口令比对是常数时间的（仅泄漏长度）。

**登录失败限流** `server/loginThrottle.js`：

| 项 | 值 |
| --- | --- |
| 计数载体 | R2 对象 `auth-throttle/<sha256(身份).slice(0,32)>.json` |
| 身份 | `x-forwarded-for` 首个地址，回退 `x-real-ip`，都没有则 `unknown` |
| 记录结构 | `{ failures, lockedUntil, updatedAt }` |
| 阈值 | 连续失败 5 次后开始锁定 |
| 锁定时长 | `30s × 2^(failures-5)`，封顶 15 分钟 |
| 计数窗口 | 距上次失败超过 1 小时则计数归零 |

因为写在 R2 上，限流跨 Serverless 实例生效。**存储故障一律放行（fail-open）**——`checkLoginAllowed` / `recordLoginFailure` / `clearLoginFailures` 都各自 catch 并打警告，避免限流本身成为把自己锁在门外的原因。命中和失败都会刷新 `updatedAt`，所以持续攻击者会一直停留在锁定状态。

触发限定时 `POST /api/auth?action=login` 返回 **429** 并带 `retry-after` 头。

**分享 token**：`createShareToken({ key, expiresAt, purpose })` = `base64url(JSON{key,expiresAt,purpose})` + `'.'` + HMAC。`verifyShareToken(token, { purpose, allowLegacy })` 按**最后一个 `.`** 切分、验签、解码并要求 `key && expiresAt && expiresAt >= now`，任何异常返回 `null`。

`purpose` 区分「播放」与「上传」两种凭证；`allowLegacy` 只给播放校验开启，用于放行本次修复前发出、payload 里没有 `purpose` 字段的二维码链接。上传凭证没有历史包袱，因此严格匹配 `purpose`。

`Secure` 标志**依赖 `VERCEL_ENV` 的存在**：迁到非 Vercel 平台部署时会静默失去 `Secure`。

### 5.3 R2 对象存储 `server/r2.js`

全部基于 `@aws-sdk/client-s3`（S3 兼容 API）。客户端懒加载单例，`region: 'auto'` + `forcePathStyle: true`（R2 必需）。

| 导出 | 说明 |
| --- | --- |
| `getR2Client` | 懒加载单例；缺 env 抛 500 |
| `getShareTtlMs` | `TTS_SHARE_TTL_DAYS`（默认 3650 天）；非有限或 ≤0 回退 3650 |
| `createPutUrl` | 预签名 PUT，15 分钟。**⚠ 全仓库无调用点（死代码）** |
| `createGetUrl` | 预签名 GET，默认 24 小时 |
| `putObject` | 支持 `IfMatch` / `IfNoneMatch`——**乐观并发与去重的底层能力** |

**共享工具 `server/tts.js`**：

| 函数 | 说明 |
| --- | --- |

- `segmented: true` 时**逐词串行** `await synthesize(word)`，响应返回 `segments[{ text, audioBase64, contentType }]`。`pauseMs` **仅回传，服务端不插静音**。

### 5.5 分享与签名 token

整体是**四步客户端编排，服务端无状态机**——服务端只做「签名授权 + R2 读写」。

**`POST /api/share/start`**：`count = clamp(1..1000)`；生成 `shareId = randomUUID()`、`prefix = tts-shares/{shareId}`、`expiresAt = now + getShareTtlMs()`；对每个文件按 `sourceIndex` 计算 `batchLabel` 与路径。返回**两种凭证**：

| 凭证 | 绑定的 key | purpose | 有效期 |
| --- | --- | --- | --- |
| `token` | `{prefix}/manifest.json` | `listen` | `TTS_SHARE_TTL_DAYS`（默认 3650 天） |
| `uploadToken` | `{prefix}`（前缀本身） | `upload` | 12 小时 |

播放 token 只绑定 `manifest.json`，音频通过 manifest 间接授权（读取端再为每个 track 现签 URL）。上传 token 只在创建分享后的写入阶段使用，把有效期从十年压到 12 小时。

**批次命名规则**（服务端 `start.js:5-24`，客户端有等价实现 `TtsWorkspace.jsx:64-99`）：

- `sanitizeName`：trim → 小写 → 去 `'`/`’` → 非 `[a-z0-9._-]` 换 `-` → 去头尾 `-` → **截断 24 字符** → 空则 fallback
- `pad3`：3 位补零，最小 1
- `buildBatchLabel`：`001_first_30w`；首尾词不同则 `001_first-to-last_30w`

客户端把 `batchFirstWord/batchLastWord/batchWordCount` 传给服务端，**服务端重新计算 slug**（避免路径注入），并以服务端结果为准回填 `batchLabel/folder/fileName`。

**TTL 生效链路**：`TTS_SHARE_TTL_DAYS` → `getShareTtlMs()` → `start.js` 写入 `expiresAt` → 进签名 payload → 读取时 `verifyShareToken` 校验。**客户端 manifest 里的 `expiresAt` 只是展示字段，权威过期时间在签名 token 内。**

**`POST /api/share/upload`** 的写入校验集中在 `server/sharePolicy.js`，四道关：

1. **归属**：必须携带 `uploadToken`，验签通过且 `purpose === 'upload'`；目标 key 必须落在 token 绑定的前缀下（`isKeyUnderPrefix`）。知道 UUID 也无法写别人的分享。
2. **路径形状**：`SHARE_KEY_RE`
   ```
   ^tts-shares/[0-9a-f-]{36}/(manifest\.json | [a-z0-9._-]{1,96}/[a-z0-9._-]{1,120}\.mp3)$   (/i)
   ```
3. **内容类型**：manifest 只接受 `application/json`，音频只接受 `audio/mpeg`（`normalizeContentType` 先剥掉 `; charset=` 等参数）。不再能写入任意 MIME 对象。
4. **体积**：manifest ≤ 4 MB，单个 mp3 ≤ 16 MB，超限返回 **413**。

内容取 `base64` 优先、其次 `text`，都没有则 400。直写 R2。

**`POST /api/share/finalize`**：仅返回 `{ ok: true }`，**空操作**——不校验完整性、不写状态、忽略 `shareId`。属于冗余接口。

**`GET /api/share?token=`**（**无需会话**）：验签（`purpose: 'listen'` + `allowLegacy: true`）→ 要求 key 是 manifest 形状 → 生成 **10 分钟**预签名 GET 读 manifest（404 若不存在）→ **逐个校验 `track.key`** 必须匹配 `SHARE_KEY_RE` 且落在同一分享前缀内、且不是 manifest 本身 → 为通过的 track 现签 **1 小时** URL → 返回 `{ ok, manifest: { ...manifest, tracks: [...] }, expiresAt }`。

> 读取侧的 track 校验是必要的：manifest 是对象存储里的数据，若不校验就为 `track.key` 签发 URL，被篡改的清单能让服务端为桶内任意对象（例如 `worksheet-jobs/<id>/artifact.zip`）签发可读链接。不匹配的 track 会被静默过滤掉，而不是报错。

### 6.4 校验规则

**`sanitizeLexical`**：

- `definition_en` / `definition_zh` 必填。
- **禁止释义回声**：目标词 ≥3 字母且不在停用词表中时，若 `containsWholeWord(definitionEn, displayEnglish)` 命中即抛错——防止模型用「the act of X-ing」这类循环释义。
- synonym / antonym 经 `normalizeRelationTerm` 规范化后，若是目标词的**形态变体**（`isMorphVariant`：词干相同，或前缀包含且长度差 ≤5）则丢弃为空串。

**`sanitizeMaterial`**：

- 同义分支：`synonym` / `synonym_original` 必填；`synonym_rewrite_blank` 必须**恰好 1 个空格**且不含答案，否则用 `replaceAnswerWithBlank(rewriteFull, synonym)` 重算；仍失败抛错。
- 基础分支：`tf_true` / `tf_false` 必填；`clozeSentence` 由 `buildClozeSentence` 从 `cloze_full_sentence`（或 tf 句兜底）生成，必须恰好 1 个空。

`resolveResponseItems` 按 `id/ID/key/input_id/inputId` 建 Map 匹配；若响应数组长度与请求条目数相等且该位置 id 不在输入集合内，则**按下标兜底**。

### 6.5 失败处理阶梯

这是本项目最复杂的一段逻辑，分**引擎内**与**队列层**两级。

**引擎内** `resolveLlmEntries`（`genEngine.js:1362`）：

```
按 batchSize 切块 → runWithConcurrency 并发
  ↓ 有未解析条目
while (pending.length > 1 && subBatchSize > 1 && guard < 12):
  ├─ resolvedCount === 0 且 chunk.length > 1 → LLM_BATCH_REJECTED（整批作废，交队列降 batch）
  ├─ 其他 chunk 异常 → 该 chunk 全部词条计入 pending 重试
  └─ subBatchSize = floor(ceiling / 2)               ← 「拆单」逐轮减半
  ↓ 剩余单条
runWithConcurrency(pending, min(3, len)) → resolveSingleEntryStrict
  ├─ tryModelForSingleEntry × singleItemRetries（默认 2）
  │    ├─ 失败 → callLlmForSynonymRepair           ← 「修复」
  │    └─ 失败 → callLlmForSynonymDoctor           ← 「doctor」
  └─ 再试 1 个 fallback 模型（slice(0,1)）
  ↓ 仍失败
createLlmResolutionError → code = LLM_GENERATION_INCOMPLETE
```

关键设计：

- **`LLM_RATE_LIMITED` / `LLM_REQUEST_FAILED` 穿透所有本地重试**，交由 durable 队列处理。源码注释（`genEngine.js:1398`）明确说明：「Model rotation is handled by the durable queue so every retry is checkpointed and visible」——本地不做模型轮换，因为只有队列的重试才可持久化、可观测。
- `repair` / `doctor` **只在同义替换阶段挂载**；词汇与基础题面阶段没有。
- `resolveSingleEntryStrict` 只试 **1 个**备用模型（`fallbackModels.slice(0,1)`），不是遍历整条链——跨 attempt 的模型轮换由队列负责。

**队列层二次降级**（`server/genQueue.js`）：

| 引擎错误码 | 队列处理 | 行 |
| --- | --- | --- |
| `LLM_BATCH_REJECTED` | `llmBatchSize = floor(current/2)` 后 re-queue，并回写 payload | 820 |
| `LLM_GENERATION_INCOMPLETE` | **补跑**：保留 cache 与 progress，计数 +1，按退避延迟 re-queue；运行参数由 `tuneLlmRuntimeAfterValidationFailure` 降级 | 923 |
| `LLM_REQUEST_FAILED && retryable` | `tuneLlmRuntimeAfterRequestFailure` + `getLlmRequestRetryDelayMs` re-queue | 873 |
| `LLM_RATE_LIMITED` | `tuneLlmRuntimeAfterRateLimit` + `computeRateLimitDelayMs` re-queue | 988 |
| `JOB_STEP_YIELDED` | progress 已刷盘，**重置全部重试计数**，1 秒后 re-queue | 794 |

「补跑」之所以有效，是因为每批成功后 `onCacheCheckpoint` 会把已解析条目写进 R2，下一轮 `ensureLexicalData` / `ensureMaterials` 用 `cache.has(key)` **跳过已完成的词**。

### 6.6 多模型与限流

**模型池**：`VIVI_LLM_MODELS` 支持 JSON 数组、`{ models: [...] }` 包装、换行或逗号分隔三种写法（`parseLlmModelOptions`）。主模型是 `VIVI_LLM_MODEL`。

**备用链优先级**（`getFallbackLlmModels`）：

1. `VIVI_LLM_FALLBACK_MODELS` 中按主模型名精确匹配的数组；
2. 否则取其中的 `default` 数组；
3. 否则自动 = 全部可用模型去掉主模型，并用 `orderWorksheetFallbackModels` 把含 `4b` / `8b` 的**低容量模型排到链尾**。

**429 处理**：

- `isRetryableLlmStatus` 把 `400/408/409/425/429/5xx` 视为可重试。429 时错误对象带 `code='LLM_RATE_LIMITED'`、`status`、`retryAfterMs`（解析 `Retry-After` 头，支持秒数与 HTTP-date）、`responseDetail`（截 300 字）。
- `fetchLlmArray` / `fetchLlmObject` 内层遇到 429 **立即 break，不做本地重试**。
- 队列层退避 `computeRateLimitDelayMs` = `max(10s, header 值, 10s × 2^min(5,n))` + ≤1.5 s 抖动，封顶 `VIVI_LLM_RATE_LIMIT_MAX_DELAY_MS`（120 s）。
- 降级 `tuneLlmRuntimeAfterRateLimit`：① 有备用模型 → 切到链首、当前模型挪到链尾，并发 -1；② 并发 >1 → 并发 -1；③ 批次 >1 → 批次减半；④ 否则只等待。

**「有进展就清零」的计数重置**：`getLlmRetryProgressMark` = `[completedSteps, completedStepKeys.length, stageWordCompleted].join(':')`。每次重试前对比上次 mark，**只要有实质进度就把重试计数归零**——避免长任务被累计计数误杀，让任务可以无限期「前进式重试」，只有纯空转才累计并进入长退避。

**长恢复退避**：超过 8 次重试后 `getLlmRequestRetryDelayMs` 进入 `300s → 600s → 900s` 封顶模式（前 8 次是 `3s × (n+1)`，上限 `GEN_QUEUE_MAX_INTERNAL_WAIT_MS`）。

**请求失败的降级顺序**（`tuneLlmRuntimeAfterRequestFailure`）：`400` → 优先减半批次以定位被拒条目 → `400/401/403` → 轮换模型 → 有进度则参数不变只补跑 → 并发 -1 → 轮换模型（并发保 1）→ 批次减半 → 最低并发等待。

**校验失败的降级顺序**（`tuneLlmRuntimeAfterValidationFailure`）：批次减半 → 并发 -1 → 轮换模型。

### 6.7 缓存机制

需区分**两套同名但完全不同**的概念：

**（1）LLM 结果缓存**（真正的生成缓存）

- 载体：R2 对象 `worksheet-jobs/<jobId>/cache.json`，结构 `{ lexical: {}, basic: {}, synonym: {} }`。
- 粒度：**以词条为键**，key = `materialKey` = `` `${cleanEnglish}||${plainChinese}` ``。同一词条在不同分组、不同题型间命中同一份数据。
- 写入：每批解析成果累积后触发 `context.onCacheCheckpoint`；异常路径也强制落盘。落盘函数 `checkpointCache` **先校验执行租约**再写，防止被新执行器或已取消任务覆盖。
- 读取：每次 attempt 开头读 `cache.json` 恢复到三个 Map。
- 跨任务复用：提交时带 `cacheSourceJobIds`，`seedWorksheetJobCaches` 把多个源 cache 合并进目标任务；合并语义是 **`{ ...source, ...target }`——已有结果优先**。
- 生命周期：任务成功后**保留**（供 `reexportWorksheetJob` 免 LLM 重排）；取消时删除。

**（2）`shared/cacheGroups.js`**（前端「缓存来源」分组 UI 助手，**不是 LLM 缓存本体**）

`dedupeCacheJobs` 过滤 `cacheReady` 的任务，按 `createdAt` 升序，按签名分组（有 `batchId` 用 `batch:${batchId}`，否则 `cacheSignature || id`），让 UI 把一个批次的 N 份副本当作**一个可勾选的缓存来源**。

`cacheReady` / `cacheSignature` 由 `listJobStates` 计算：遍历 R2 列出的 `*/cache.json`，用 **对象 ETag + Size** 拼签名 `` `${etag}:${size}` ``。因此「同一批缓存」= 内容字节完全一致。

### 6.8 抽样与多份变体

`selectCoverageWindow(items, count, seed, copyIndex)`：按 seed 打乱后按 `copyIndex` **轮转偏移**取样，使第 N 份测试卷取到不同词集，且在重复之前先轮完全部单词。9 个不同种子能产出 9 套不同题集（有测试覆盖）。

## 7. 持久化队列与 Workflow

`server/genQueue.js`（1695 行）是本项目最核心的服务端模块。

### 7.1 自调度队列模型

**这不是「生产者—消费者」队列**：没有独立 worker、没有内存队列、没有并发池。

- 「排队」完全由 R2 上 `job.json` 的 `status` + `nextAttemptAt` 表示。
- 「调度」由 Vercel Workflow 的持久化 `sleep()` 循环完成。

驱动循环（`workflows/worksheetJob.js:19`）：

```js
export async function worksheetJobWorkflow(jobId) {
  'use workflow'
  while (true) {
    const job = await runWorksheetJobAttempt(jobId)      // 'use step'，maxRetries = 20
    if (TERMINAL_STATUSES.includes(job.status)) return job
    const delayMs = Math.max(1000, Number(job.resumeAt || 0) - Date.now())
    await sleep(delayMs)                                 // 持久化 sleep，不占计算配额
  }
}
```

调度契约的核心是 step 返回值里的 `resumeAt`（`processWorksheetJobAttempt`）：

```js
if (TERMINAL_STATUSES.has(job.status)) return { ...summarizeJob(job), resumeAt: 0 }
const resumeAt = job.status === 'processing' || job.status === 'canceling'
  ? Number(job.updatedAt) + STALE_PROCESSING_MS        // 本次 attempt 的租约到期时刻
  : Number(job.nextAttemptAt || 0)                     // 队列写入的退避时刻
if (resumeAt > currentTime) return { ...summarizeJob(job), resumeAt }
await processSingleJob(job)
```

要点：**每次 step 调用都重新读 R2 决定要不要干活**，所以「排队等待」不消耗 Function 执行时间。`resumeAt` 对 `processing` / `canceling` 返回 `updatedAt + STALE_PROCESSING_MS`——这正是「失联接管」能自动发生的原因：**同一个 workflow run 自己就会在 6 分钟后重入一个僵死的任务**。

前端仅做 3500 ms 轮询展示，**不参与驱动**。

批处理 `worksheetJobBatchWorkflow`（`worksheetJob.js:31`）用 `for` 循环**串行**跑每份拷贝，任一份 failed 就调 `stopWorksheetJobBatch` 把剩余份全部标记失败（消息「批次因第 N 份失败而停止：…」）。

### 7.2 状态机

```
queued ──processSingleJob 抢锁──▶ processing ──成功──▶ completed
  │                                    │
  │                                    ├─ JOB_STEP_YIELDED ──▶ queued (now+1000)
  │                                    ├─ LLM_* 可重试 ─────▶ queued (now+退避)
  │                                    ├─ LLM_BATCH_REJECTED ▶ queued (batch 减半)
  │                                    ├─ JOB_CANCELED ──────▶ canceled (+删 cache.json)
  │                                    └─ 其他异常 ─────────▶ failed
  ├─ 取消(queued) ────────────────────▶ canceled（立即）
  └─ 取消(processing) ────────────────▶ canceling ──执行器轮询到达──▶ canceled
                                        canceling ──超 STALE 无写入──▶ canceled
```

- 可取消集：`{queued, processing, canceling}`
- 终态集：`{completed, failed, canceled}`

`completed` / `failed` 可由 `reexportWorksheetJob` **重新打包而不重调 LLM**；`failed` 可由 `retryWorksheetJob` 新建任务（会复制源任务的 cache，实现零 LLM 重跑）。

### 7.3 R2 对象布局与数据模型

前缀 `JOB_PREFIX = 'worksheet-jobs'`：

| key | 内容 | 说明 |
| --- | --- | --- |

### 7.4 进度上报与落盘节流

**引擎侧**统一走 `context.reportProgress(payload)`；`report` 包装器在回调**前后各检查一次取消**。

**队列侧聚合** `progressFromEvent`（`genQueue.js:211`）保证：

- **单调不回退**：`percent = max(prev, next)`；
- 同阶段内 `stageWordCompleted` 只增不减；
- `stepDelta` 用 `completedStepKeys` **去重**，保证 Workflow 重放不重复计数；
- `inProgressSteps` 被「尚未完成的 stepKey 数」夹紧。

总步数 `buildTotalSteps` = 试卷份数（或题型数）+ 词汇预热 1 + 基础材料 1 + 同义材料 1。

**落盘节流** `persistProgress`：满足**任一**条件才写 R2——`force`、首次、阶段变化、`stageWordDelta ≥ 5`（渲染阶段 200）、`completedStepDelta ≥ 1`、间隔 `≥ 700ms`（渲染阶段 5000ms）、`percent ≥ 100`。

四个值得注意的性质：

1. **比较基准是上次已落盘的快照**，不是上一个事件——被节流丢弃的事件不会累积偏差。
2. **`intervalElapsed` 独立成立即可 flush**，等于约 700 ms 一次**心跳写**。心跳有两个副作用：刷新 `updatedAt`（对抗接管）和刷新 ETag（顺带做一次所有权活性校验）。
3. **每次 flush 都是条件写**——写入节流与互斥是同一段代码。
4. `renderingStarted` 置位后**禁止 yield**（避免产出半个 ZIP），所以渲染期必须靠 5 秒心跳维持租约。

并发事件通过 `progressChain` / `cacheChain` 两条 promise 链串行化，避免引擎并发回调交叉写。

### 7.5 取消

三层实现：

**（1）写侧** `cancelWorksheetJob`：非可取消状态原样返回（幂等）；`queued` → **直接** `canceled`；`processing` → `canceling`，进度文案「正在停止任务，请等待最后一次调用完成…」。

取消**优先走条件写入**：读取带 ETag 的快照 → `writeOwnedJob`，避免用略旧的快照覆盖执行器刚刷新的进度。若连续 3 次被抢占（执行器每 700 ms 就在写心跳），会退回无条件写入——因为取消是用户的明确意图，必须落地。退回前会重新读一次状态并确认仍是可取消状态，防止把已进入终态的任务改回 `canceling`。

**（2）执行侧轮询**：

```js
const shouldCancel = async (force = false) => {
  if (cancelKnown) return true                       // 一旦为真永久为真，不再读 R2
  const elapsed = now() - lastCancelCheckAt
  if (!force && lastCancelCheckAt && elapsed < CANCELLATION_POLL_INTERVAL_MS) return false
  lastCancelCheckAt = now()
  const current = await readLatestJobState(job.id)   // 单次 GetObject
  cancelKnown = ['canceling','canceled'].includes(current?.status)
  return cancelKnown
}
```

`GEN_QUEUE_CANCELLATION_POLL_INTERVAL_MS`（默认 300 ms，下限 150）是**两次 R2 读之间的最小间隔**，而非定时器——检查点由引擎驱动。引擎在每个进度上报前后、每组渲染循环开头、PDF 渲染前后、每个 LLM 批次前调用，因此**进度事件越密集，取消响应越快**。

`ensureNotCanceled(true)` 强制读 R2，用于两处关键位置：开工前，以及**写入 artifact 前**——避免「取消后仍产出文件」。

**（3）收尾**：`JOB_CANCELED` → 写 `canceled` + **删除 `cache.json`**。同样的「取消优先」分支在三处重试路径里重复出现，确保等待重试中的任务被取消时不复活。

**写入安全约定**：`job.json` 的一切状态变更都必须走条件写。

- 执行器内部统一走 `writeJobTransitionIfOwned(jobId, buildPatch, { allowStatuses })`——它在写入前重新取 ETag、确认任务仍归本执行器所有（重试入队与失败落库要求 `allowStatuses: ['processing']`），返回 `null` 表示「没写成，也不是错误」。**执行器源码中不允许出现裸 `writeJob(` 调用**，有测试守着这条不变量。
- `settleStaleCanceledJobs`（列表路径收敛超时 `canceling`）、`processWorksheetJobAttempt`（收敛超时 `canceling`）、`failWorksheetJobStart`（Workflow 启动失败）同样走条件写，并在 `JOB_OWNERSHIP_LOST` 时静默让位。
- 例外只有两处，都是刻意为之：`prepareWorksheetJobWorkflowMigration`（运维接管，需要强制作废旧租约）与 `cancelWorksheetJob` 的兜底（取消必须落地）。

这些约束共同保证：**谁都不会覆盖仍在写进度的执行器状态，取消也不会被重试入队悄悄丢弃**。

### 7.6 租约、失联接管与恢复

**`GEN_QUEUE_STALE_PROCESSING_MS`（默认 360 s）的语义是「最后写入时间」的容忍窗口，不是执行时长限制**。判据始终是 `now() - job.updatedAt`，而 `updatedAt` 在每次写入时刷新。因此：

- 持续写进度的执行器**永远不会**被判为僵尸；
- 被 kill 的执行器会在 6 分钟后被接管。

三处消费：`processWorksheetJobAttempt`（计算 `resumeAt`）、`settleStaleCanceledJobs`（列表时收敛超时的 `canceling`）、入口处的 `canceling` 收敛。

**接管不双跑的四重保证**：

1. **抢占**：`readJobWithMetadata` 拿 `etag` → `writeOwnedJob({ ...latest, status:'processing', executionLeaseId }, etag)`。
2. **条件写**：`IfMatch: etag`；R2 返回 **412 PreconditionFailed** 时抛 `JOB_OWNERSHIP_LOST`。若 R2 未回 ETag 则主动抛错（「已停止执行以避免重复任务」）。
3. **租约 ID**：每次 attempt 生成新 `executionLeaseId = crypto.randomUUID()`。因 `cache.json` 是**无条件写**的，必须额外用 `hasWorksheetExecutionLease` 挡住旧执行器。
4. **静默退出**：所有 `JOB_OWNERSHIP_LOST` 分支 `return` 而不写任何状态——旧执行器绝不允许覆盖新执行器的状态。

**时间预算与接管的配合**：`GEN_QUEUE_WORKFLOW_STEP_SOFT_LIMIT_MS`（默认 180 s）让引擎主动让位并回写 `queued`。**3 分钟（主动让位）< 6 分钟（失联判据）**——正常路径永不触发接管，接管只为真正的进程死亡兜底。

**人工接管** `POST /api/gen/jobs/recover`：可取消旧 run、清空 `executionLeaseId`（让在飞的旧执行器立刻失效）、重置重试计数、按有无 cache 决定是否重置运行参数，最后用**最新部署**重启 workflow。批次模式还能按 `copyCount` 补齐缺失份。前端**没有调用点**，是运维/CLI 专用接口。

### 7.7 批次与多份生成

提交时（`handlers/gen/jobs.js`）：`copies = clamp(1, 20)`；`copies > 1` 时生成 `batchId`，为**每一份独立提交一个 job**，带 `copyIndex` / `copyCount` / `variationSeed` / `exportSuffix = 第NN份`。

前端用 `shared/jobBatches.js` 的 `collapseBatchJobs` 把同一 `batchId` 的行折叠为一条：

- 状态优先级 `canceling > processing > queued > failed > 全部 completed > canceled`
- 进度按词数加权：`Σ(wordCount_i × percent_i/100) / ΣwordCount_i`
- `artifactReady` 要求**全部** completed 且 artifactReady

### 7.8 并发与互斥

分六个层面，**没有**进程内全局信号量：

| 层面 | 机制 |
| --- | --- |
| 同 job 跨执行器 | ETag `If-Match` + `executionLeaseId`——唯一的硬互斥原语，靠 R2 原子性与 412 实现 |
| 同 job 内写入 | `progressChain` / `cacheChain` 两条 promise 链 |
| 批内 | workflow 用 `for` 串行，一份失败则中止其余 |
| 提交去重（扫描） | `buildJobFingerprint`（SHA-256 over rows + 全部参数）扫描 queued/processing 任务 |
| 提交去重（占位） | `acquireJobLock` 用 `IfNoneMatch: '*'` 原子写 `worksheet-jobs/locks/<fingerprint>.json` |
| LLM 并发 | 每任务独立，`VIVI_LLM_BATCH_SIZE` / `VIVI_LLM_CONCURRENCY`，无跨任务配额 |

**两级去重**：扫描负责常见情况与良好体验（能直接返回已存在的任务），占位负责堵住竞态窗口。

`acquireJobLock(fingerprint, jobId)` 的语义是「返回 `null` 表示抢到占位，返回任务摘要表示同指纹任务已在跑」：

1. `putObject({ ifNoneMatch: '*' })` 写入 `{ jobId, createdAt }`。
2. 若返回 **412**，说明占位已存在：读出它，检查其 `jobId` 指向的任务是否仍是 `queued`/`processing`。
   - 是 → 直接返回该任务，调用方复用（`created: false`）。
   - 否（已进入终态或对象已消失）→ 删除过期占位并重试，最多 3 轮。

因此**占位不需要 TTL**：是否算重复由持有任务的实时状态决定，持有者进入终态后，下一次同指纹提交会顺手清理。任务写入失败时 `releaseJobLock` 会释放占位，避免占位泄漏。

批量副本（`copies > 1`）与带 `cacheSourceJobIds` 的提交走 `allowDuplicate: true`，显式跳过两级去重——它们本来就需要产生多份任务。

### 7.9 列表读取的并发上限

`listJobStates` 需要为每个 `job.json` 单独发一次 GetObject（R2 没有批量读）。任务累积到数百时，一次性 `Promise.all` 会同时发起数百个请求。

`mapWithConcurrency(items, limit, worker)` 提供有界并发（默认 12，`GEN_QUEUE_LIST_READ_CONCURRENCY`），按下标回填结果以保持顺序。这降低了并发峰值，但不减少请求总数——真正的修法仍需引入索引对象（见 [14.1](#141-listjobstates-仍是-n1-次读取)）。

## 8. 产物格式

### 8.1 ZIP 写入器 `server/zip.js`

**自实现的 STORE-only（method 0，不压缩）ZIP 读写器**，包含 CRC32 表、DOS 时间转换、本地文件头/中央目录/EOCD。

**中文文件名处理**：恒置通用位标记 `ZIP_FLAG_UTF8 = 0x0800`，并对含非 ASCII 字节的文件名额外写 Info-ZIP **Unicode Path Extra Field `0x7075`**，兼容老旧解压器。

**为什么选 STORE 而不是 DEFLATE**：这是功能需求而非偷懒。批量下载合并依赖 `extractStoredZipFiles` 零依赖地读回条目，而该读取器**只支持未压缩条目**，遇到 method ≠ 0 抛「批量下载只支持本站生成的未压缩 ZIP。」代价是产物偏大（docx/pdf 本身已压缩，影响有限）。

### 8.2 DOCX 生成器 `server/docx.js`

**用字符串模板手搓 OOXML**，打包 9 个 part：`[Content_Types].xml`、`_rels/.rels`、`docProps/core.xml`、`docProps/app.xml`、`word/document.xml`、`word/styles.xml`、`word/_rels/document.xml.rels`、`word/settings.xml`、`word/webSettings.xml`。

**未使用 `docx` npm 包**（依赖中确实不存在），生成成本极低。

支持的排版能力：

| 能力 | 实现 |
| --- | --- |
| 多栏 | `buildSectionPropertiesXml` 的 `<w:cols w:num w:space>` |
| 页面尺寸与页边距 | twips 单位 |
| 防跨栏跨页 | `keepNext` / `keepLines`（用于 `pushQuestionWithOptions`） |
| 选项对齐 | `tabs` |
| 分栏符 | `<w:br w:type="column"/>` |
| 无框线布局 | `buildTableXml` 全部边框 `nil` |
| 行距 | `w:line = 行距 × 240`，`lineRule="auto"` |

**中文字体靠名称引用**（`w:rFonts w:eastAsia="宋体"`），**不嵌入字体**，依赖客户端字体——这与 PDF 路径（`pdf-lib` + fontkit **子集嵌入**）是相反的策略。

### 8.3 服务端 PDF（翻译题）

只有「十_汉译英」「十一_英译汉」两个题型输出 PDF（需要精确的分栏排版与 CJK 字体控制）。

`chooseTranslationLayout`（`genEngine.js:2618`）遍历 **8 种候选**（4 栏/3 栏 × 10.5/10/9.5/9/8.5 pt），逐题 `buildTranslationBlock` 用真实字体 `font.widthOfTextAtSize` 折行、贪心装入多栏，评分 `[fontSize, 是否用满所有栏, -栏内题数极差, 栏数]` 取最优；全部候选失败才退化为 3 栏 8.5 pt 顺序排版。

### 8.4 产物目录树与命名

`exportName = sanitizeExportName("<文件名去扩展名> 测试卷包|练习包 [exportSuffix]")`，ZIP 自身名为 `${exportName}.zip`。

**固定测试卷模式**：

```
<exportName>/
  <100词一组 | 20词一组 | 全部单词一组>/     ← 每个配置的分组尺寸一段
    1-100测试卷.docx                        ← 8 大题 + 文末「参考答案」
    101-200测试卷.docx
```

- `100词一组` 时每份 docx 页首有「词汇库：…」；**`全部单词一组` 时省略**
- 标题为 `英语词汇专项测试卷<start>-<end>`
- 答案以 `addTestPaperAnswerSection` 追加在同一 docx 末尾

**练习包（legacy）模式**：

```
<exportName>/
  一_释义匹配/一_释义匹配.docx + 一_释义匹配答案.docx
  二_选择题/二_选择题.docx + 二_选择题答案.docx
  ...
  十_汉译英/十_汉译英.pdf + 十_汉译英答案.pdf      ← 仅十/十一走 PDF
```

即**同一 ZIP 内混合 docx 与 pdf**。

**批量下载再打包**（`POST /api/gen/jobs/download`）：取 N（≤20）个已完成任务的 ZIP，`extractStoredZipFiles` 扁平化，重命名为 `NN_<原文件名>`（`padStart(2,'0')`，重名追加 `_2`），再重新打包为 `<基名> 批量下载 <N>份.zip`。**合并后目录层级被拍平**，仅靠序号前缀区分来源。全程在内存中完成，无流式、无临时文件。

**`server/downloadNaming.js` 只管 HTTP 下载文件名，不参与 ZIP 内部条目命名**——这是一个容易误读的点。`getWorksheetDownloadFileName` 会**幂等地**追加分组标签（判断 `stem.endsWith(groupLabel)`，避免 `xxx 100词一组 100词一组.zip`）。

### 13.4 [`genQueue.js`] 无条件写覆盖执行器状态或丢弃取消 ✅

这是本次最严重的一类缺陷，分两处：

**（a）收敛与启动失败路径**：`settleStaleCanceledJobs`（列表路径）、`processWorksheetJobAttempt` 的收敛分支、`failWorksheetJobStart` 都用无条件 `writeJob`。若执行器恰在此时刷新了进度，写入会把 `updatedAt` / `progress` / `executionLeaseId` 回滚，进而让执行器失去租约。

**（b）重试入队与失败落库**：`processSingleJob` 的 catch 分支（`LLM_REQUEST_FAILED` / `LLM_GENERATION_INCOMPLETE` / `LLM_RATE_LIMITED` 的重试入队、`JOB_CANCELED` 与通用失败的收敛）共 **7 处**使用无条件写。其中重试入队写入的是 `status: 'queued'`——如果用户在「读取最新状态」与「写入」之间点了取消，这次写入会把 `canceling` **覆盖回 `queued`**，取消被丢弃，任务继续消耗 LLM 配额。这是花钱的缺陷。

统一修法是引入 `writeJobTransitionIfOwned(jobId, buildPatch, { allowStatuses })`：

```js
const writeJobTransitionIfOwned = async (jobId, buildPatch, { allowStatuses } = {}) => {
  const snapshot = await readJobWithMetadata(jobId).catch(() => null)
  const current = snapshot?.value
  if (!current) return null
  if (allowStatuses && !allowStatuses.includes(current.status)) return null
  try {
    return (await writeOwnedJob({ ...current, ...buildPatch(current) }, snapshot.etag)).job
  } catch (error) {
    if (error?.code === 'JOB_OWNERSHIP_LOST') return null
    throw error
  }
}
```

- 重试入队与失败落库传 `allowStatuses: ['processing']`——执行器只在持有 `processing` 时才允许改状态；一旦变成 `canceling`/`canceled` 或已被运维迁移重置，就放弃本次变更。返回 `null` 表示「没写成，也不是错误」，调用方直接 `return`，连 payload 回写一并跳过。
- 取消收敛不传 `allowStatuses`（目标状态本身就是 `canceled`）。
- 补丁现在以**刚读到的 `current`** 为基底，而不是先前可能已经过期的 `retryBaseJob`。

`cancelWorksheetJob` 另外保留一条**无条件写入兜底**：取消是用户明确意图，连续 3 次被抢占后退回无条件写，但退回前会重新确认任务仍处于可取消状态，避免把已终态的任务改回 `canceling`。

**回归防护**：新增的「队列执行器内部不使用无条件写」测试会切片 `processSingleJob` 的源码，断言其中不出现裸 `writeJob(` 调用。已验证该断言在模拟回归时会失败（0 → 1 次匹配），不是空转。

### 13.5 [`genQueue.js`] 提交去重的 TOCTOU 竞态 ✅

原实现「扫描 queued/processing 任务 → 写入新任务」之间无锁，并发同指纹提交会同时通过检查，**真的产生两个任务并各跑一遍 LLM**。

现在加了一层 `IfNoneMatch: '*'` 的原子占位（`worksheet-jobs/locks/<fingerprint>.json`）。扫描仍然保留（负责良好体验），占位负责堵住竞态窗口。占位**不需要 TTL**：是否算重复由持有任务的实时状态决定，持有者进入终态后下一次同指纹提交会顺手清理；任务写入失败时会释放占位。

### 13.6 [`share/upload.js` + `share/index.js`] 分享读取与写入缺归属校验 ✅

**写入侧**：`SHARE_KEY_RE` 只校验路径形状，知道 UUID 的任一登录者即可覆盖他人的 manifest 或音频，且无体积上限、无 MIME 白名单。

现在 `start` 额外下发绑定分享前缀的 `uploadToken`（12 小时有效），`upload` 强制验签 + 要求目标 key 落在该前缀内，并按目标文件校验内容类型（manifest 只收 `application/json`、音频只收 `audio/mpeg`）与体积（manifest ≤ 4 MB、单个 mp3 ≤ 16 MB）。规则集中在 `server/sharePolicy.js`，读写两端共用。

**读取侧**（同批发现的更严重问题）：`share/index.js` 原先把 manifest 里的 `track.key` **不校验**直接送去签发预签名 URL。manifest 是对象存储里的数据，一旦被改写，就能让服务端为桶内**任意对象**（例如 `worksheet-jobs/<id>/artifact.zip`）签发可读链接。现在每个 track 都要通过 `SHARE_KEY_RE` 且落在同一分享前缀内、且不能是 manifest 本身，不匹配的静默过滤。

**兼容性**：播放 token 现在带 `purpose: 'listen'`，校验时开启 `allowLegacy`，因此本次修复前发出的二维码链接继续可用；上传凭证没有历史包袱，严格匹配 `purpose`。

### 13.7 [`handlers/auth/index.js`] 登录无尝试限流 ✅

`/api/auth?action=login` 原本没有次数限制，可无限暴力尝试共享口令。

新增 `server/loginThrottle.js`：以调用方身份为键（`x-forwarded-for` 首地址）在 R2 上记录失败次数，连续 5 次失败后按 `30s × 2^(n-5)` 锁定（封顶 15 分钟），距上次失败超过 1 小时则计数归零。命中或失败都刷新时间戳，持续攻击者会一直停留在锁定状态。触发限定时返回 **429** 并带 `retry-after`。

**存储故障一律放行（fail-open）**：三个函数各自 catch 并打警告，限流不会成为把自己锁在门外的原因。`authLogin.test.js` 专门覆盖了 R2 未配置时连续失败 8 次仍能正常登录。

### 13.8 [`genQueue.js`] 列表读取无并发上限 ✅

`listJobStates` 需要对每个 `job.json` 单独发一次 GetObject（R2 没有批量读）。任务累积到数百时，一次 `Promise.all` 会同时发起数百个请求。新增 `mapWithConcurrency`（默认 12，`GEN_QUEUE_LIST_READ_CONCURRENCY`）限制并发峰值。

**请求总数并未减少**——真正的修法（索引对象或短 TTL 缓存）仍未做，见 [14.1](#141-listjobstates-仍是-n1-次读取)。

### 13.9 [`src/pdf.js`] 字体每次导出都重新下载 ✅

`STSong.ttf` 约 11.7 MB，原本每次导出都重新 `fetch`。已加模块级 Promise 缓存（与 `templatePdf.js` 一致），失败时清空缓存以便重试。

### 13.10 其他 ✅

- **`.gitignore` 补齐** `/.nitro/`、`coverage/`、`test-results/`、`playwright-report/`。
- **`.env.example` 补充** `GEN_QUEUE_LIST_READ_CONCURRENCY`。

## 14. 剩余技术债

按影响排序，前两条建议优先处理。

### 14.1 `listJobStates` 仍是 N+1 次读取

并发上限缓解了峰值，但**请求总量不变**：`GEN_QUEUE_MAX_LIST_JOBS=1000` 只截断返回数组，不减少 GetObject 次数。前端每 **3500 ms** 轮询一次，任务累积到数百时成本可观。建议引入轻量索引对象（在状态变更时同步写一份摘要），或对列表结果做短 TTL 缓存。

### 14.2 `processSingleJob` 过长

452 行、14 个 catch 分支（`genQueue.js:612` 起）。其中 `LLM_GENERATION_INCOMPLETE` / `LLM_RATE_LIMITED` / `LLM_REQUEST_FAILED` 三个分支各自重复了约 40 行同构代码（读最新状态 → 检查取消 → 组装 retryBaseJob → tune 参数 → 算 delay → 写 job + payload）。建议抽成单一的 `requeueForRetry(kind, error)`。

### 14.3 其余

- **`GenWorkspace.jsx:42-317` 是死代码**：`buildPreviewModel` 与 6 个辅助函数无 JSX 调用点。
- **`share/finalize.js` 是空操作**（不校验完整性、忽略 `shareId`）；**`r2.js` 的 `createPutUrl` 无调用点**。两者是死代码，可删。
- **Edge-TTS 分段模式一次请求最多 80 次串行 WSS 往返**（`edge.js:31`），是函数超时的高风险路径；服务端无超时与重试控制。
- **`handlers/tts/voices.js` 无缓存**，每次调用都打 Azure。
- **`400` 被当作可重试**是刻意设计（先用更小批次定位被拒条目），但代价是确定性畸形请求会走完整条退避链（最长 8 + 3 轮，末段 300/600/900 秒）才最终 failed。建议对 400 增加熔断。
- **口令是明文共享值，会话不可吊销**：改口令不会使已签发 Cookie 失效，必须轮换 `TTS_SESSION_SECRET`。`auth.js:5` 的 `Secure` 标志依赖 `VERCEL_ENV`，迁到非 Vercel 平台会静默失去 `Secure`。
- **大字体入库**：`public/` 下的 `STSong.ttf`(11.7 MB) + 两个 `NotoSansSC-*.otf`(共 17 MB) 均已被 git 跟踪。
- **`dist/` 是过期构建产物**（已在 `.gitignore` 中）。
- **仓库根 `api/`（仅 `.DS_Store`）与 `routes/` 是历史残留**。
- **命名规则双端重复实现**（`start.js:5-24` vs `TtsWorkspace.jsx:64-99`），仍无测试锁定一致性，仅靠服务端重算兜底。
